# java-racingcar-precourse

##  구현 기능 목록

### 1. 입력 기능
- [x] 쉼표(,)를 기준으로 구분된 자동차 이름 목록을 입력받는다.
    - [x] 자동차 이름이 5자를 초과할 경우 예외를 발생시킨다.
    - [x] 자동차 이름이 공백이거나 비어있을 경우 예외를 발생시킨다.
    - [x] 자동차 이름이 중복될 경우 예외를 발생시킨다.
- [x] 시도할 횟수(이동 횟수)를 입력받는다.
    - [x] 입력값이 숫자가 아닐 경우 예외를 발생시킨다.
    - [x] 1 이상의 숫자가 아닐 경우 예외를 발생시킨다.

### 2. 도메인 로직
- [x] 입력된 이름으로 `Car` 객체를 생성한다.
- [x] `Car` 객체는 이름(`name`)과 현재 위치(`position`)를 가진다.
- [x] `Cars` 일급 컬렉션은 `List<Car>`를 관리한다.
- [x] 0에서 9 사이의 무작위 값을 생성한다.
- [x] 무작위 값이 4 이상일 경우 자동차는 1칸 전진(`move`)한다.
- [x] 무작위 값이 3 이하일 경우 자동차는 정지(`stop`)한다.
- [x] `RacingGame`은 자동차 경주를 수행하는 역할을 담당한다.

### 3. 출력 기능
- [x] 각 차수(라운드)별 실행 결과를 출력한다.
    - [x] 자동차 이름과 현재 위치를 하이픈(-)으로 표시한다.
- [x] 최종 우승자를 판별하여 출력한다.
    - [x] 가장 멀리 이동한 자동차가 우승자가 된다.
    - [x] 우승자가 여러 명일 경우 쉼표(,)로 구분하여 모두 출력한다.

## 클래스별 역할 요약

### `Application`
- 전체 애플리케이션을 시작하고 `RacingGameController`를 실행하는 진입점

### `controller`
- **RacingGameController**: 사용자의 입력을 받고(`View`), 경주 로직을 호출하며(`Domain`), 결과를 출력(`View`)하는 등 게임의 전체 흐름을 담당

### `domain`
- **Car**: 경주용 자동차의 상태(이름, 현재 위치)와 행위(전진, 정지)를 정의하는 핵심 도메인 객체
- **Cars**: `Car` 객체 목록을 관리하는 일급 컬렉션
- **RacingGame**: `Cars` 객체를 받아 경주를 실행하는 역할을 담당
- **RandomValueGenerator**: `RandomUtil` 인터페이스의 실제 구현체로,무작위 숫자를 생성하는 책임을 담당.

### `dto`
- **CarStatusDto**: `domain`의 `Car` 객체 상태(이름, 위치)를 `view`로  전달하기 위한 DTO

### `parser`
- **CarNamesParser**: 쉼표로 구분된 문자열(`"pobi,woni"`)을 `List<String>`으로 파싱하고, 예외처리 담당
- **RaceInputParser**: 시도 횟수와 같이 숫자로 된 입력을 `int` 타입으로 파싱하고, 예외처리 담당

### `util`
- **ErrorMessage**: 애플리케이션 전체에서 사용될 예외 메시지를 상수로 관리하는 열거형 클래스
- **RandomUtil**: `generateRandomNumber()` 메서드를 정의하는 인터페이스

### `view`
- **InputView**: 사용자로부터 자동차 이름, 시도 횟수 등의 입력을 받는 것을 전담
- **ResultView**: 실행 결과, 라운드별 자동차 상태, 최종 우승자 등 결과를 콘솔에 출력

## 고민한 점
- 첫 번째: 상수와 예외처리의 책임 분리

이전에는 하나의 클래스에서 모든 예외처리와 상수 관리를 통합하여 처리했습니다.
하지만 1주차 코드 리뷰를 통해, 예외처리 또한 해당 객체가 스스로 책임져야 한다는 점을 깨달았습니다.
각 객체가 자신에게 해당하는 예외처리를 직접 수행하도록 수정하였으며, 상수 또한 각 클래스 내부에서 관리하도록 변경하였습니다.

- 두 번째: 인터페이스를 활용한 난수 생성

난수를 이용한 테스트를 어떻게 할까 라는 고민이 있었는데, 
테스트 용이성을 높이기 위해 난수 생성을 인터페이스로 분리했습니다.
실제 애플리케이션 실행 시에는 랜덤한 값을 생성하도록 하고
테스트 환경에서는 고정된 값을 주입하여 일관된 테스트 결과를 보장할 수 있도록 구현하였습니다.
